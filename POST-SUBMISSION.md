# After Submission — NEXUS Follow-up

## Immediately after submitting

- Open the public app URL in a private/incognito browser and confirm it works without a team login.
- Test one no-upload request and the lecture-notes study-plan plus 10-MCQ workflow.
- Check that app, source code, slides, PRD, and video links are viewable by judges.
- Keep a copy of the submitted commit, presentation, video, and deployed version.
- Monitor app logs and Groq usage for errors or unexpected consumption.
- If any API key appeared in a commit, screenshot, or video, revoke it and replace it immediately.

## Product follow-up

- Gather judge/user feedback; assign each accepted item an owner and due date.
- Build a compact evaluation set covering tool selection, document extraction, quiz structure, and failure handling.
- Improve factual grounding/citations if real user documents need stronger evidence than the current direct-context approach.
- Consider OCR for scanned files, with a clear confidence/limitations signal.
- Decide whether to continue the project, publish a roadmap, or archive it after the event.
- Rotate shared credentials and review dependency updates after the hackathon.
